# פריסה ב־Vercel וחיבור Supabase

## מצב הפריסה הנוכחי

הרפוזיטורי החדש הוא `itaycohen5/PolicyDiff-AI-Web`. הרפוזיטורי הקודם נשאר מחובר כ־`origin`, והחדש מחובר כ־`web`.

סביבת Production מוגדרת לשימוש מלא דרך `POLICYDIFF_CLOUD_MODE=1` ו־`POLICYDIFF_STATIC_DEMO=0`. העלאת מסמכים ו־ClauseLens חי דורשים את קוד הגישה של בעל האתר. הקוד נשמר מקומית ב־`.data/hosted-access.txt`, מוחרג מ־Git, ונפרד מסיסמת המסד.

סביבת Preview נשארת במצב `POLICYDIFF_STATIC_DEMO=1`: מסמכי הדמו והתוצאות מוכנים מראש, ללא סודות Production, העלאות אישיות או קריאות מודל חיות.

פרויקט Supabase החינמי PolicyDiff AI Web נמצא באזור Frankfurt, ומזההו `dodbpfngfoocmruwpqkm`. חיבור המסד נבדק, ומיגרציות 001–007 הותקנו. פרטי החיבור נשמרים ב־Vercel כסודות Production ובקובץ המקומי המוחרג `.env.deploy.local`. קובץ `.env.local` של סביבת הפיתוח נשאר נפרד.

## למה משתמשים במסד נתונים

בגרסה המלאה של המוצר, העלאת PDF, קליטה, חיפוש, השוואה ופתיחת מקור הן בקשות שונות. מסד משותף שומר את הקשר ביניהן גם כאשר Vercel מפעילה מופעים שונים של השרת. pgvector משמש לחיפוש הסמנטי.

העדפת אחסון זמני אינה מחייבת ארכיון קבוע. מצב הענן בקוד משתמש בסביבת עבודה נפרדת לכל דפדפן, עם cookie חתום, מגבלת שני PDFs ועשר השוואות, ותפוגה לאחר שעה ללא פעילות.

נתונים שפג תוקפם נמחקים בניקוי הבא שמבוצע בתחילת בקשת POST במצב הענן. אפשר למחוק את הנתונים של סביבת העבודה הנוכחית מיד דרך Clear my workspace. תפוגת הגישה ומועד המחיקה הפיזית הם מנגנונים נפרדים. מדיניות הגיבוי והלוגים של ספקי הענן עדיין חלה.

## הגדרת חיבור בהתקנה חדשה או לאחר החלפת סיסמה

1. פתחו את [הגדרות המסד החדש](https://supabase.com/dashboard/project/dodbpfngfoocmruwpqkm/database/settings).
2. בחרו Reset password והגדירו סיסמת מסד חזקה. שמרו אותה במנהל סיסמאות.
3. בחלון Connect בחרו Direct ואז Transaction pooler. העתיקו את URI החיבור והחליפו את מציין הסיסמה בסיסמה שהוגדרה. תווים מיוחדים בסיסמה צריכים להיות מקודדים ל־URL.
4. ב־Vercel, תחת הפרויקט policydiff-ai-web, הגדירו את המשתנים הבאים כסודות בצד השרת.

| משתנה | ערך |
| --- | --- |
| `DATABASE_URL` | URI של ה־Transaction pooler, עם `sslmode=verify-full&sslrootcert=certs/supabase-prod-ca-2021.crt` |
| `POLICYDIFF_CLOUD_MODE` | `1` |
| `POLICYDIFF_STATIC_DEMO` | `0` |
| `POLICYDIFF_SESSION_SECRET` | לפחות 32 תווים אקראיים, לחתימת סביבת העבודה |
| `POLICYDIFF_ACCESS_CODE` | קוד פרטי באורך 16 תווים לפחות, המאפשר העלאה וקריאות מודל |
| `OPENROUTER_API_KEY` | מפתח OpenRouter, אם רוצים להפעיל ClauseLens חי |

יש להשאיר `POLICYDIFF_DEMO_ONLY` לא מוגדר במצב העלאות פרטיות. מפתחות אינם מקבלים תחילית `NEXT_PUBLIC_`.

5. בצעו Redeploy. בבקשת API הראשונה יופעלו המיגרציות.
6. פתחו את האתר והזינו את קוד הגישה שקבעתם. העלו שני מסמכים סינתטיים או ציבוריים לבדיקה ובדקו השוואה ופתיחת עמוד מקור.
7. פתחו חלון גלישה אחר וודאו שהמסמכים האישיים מהחלון הראשון אינם גלויים בו.

Data API כבוי בפרויקט Supabase החדש. השרת משתמש בחיבור PostgreSQL ישיר דרך pooler. מיגרציה 007 מפעילה RLS בטבלאות היישום. פעולות השרת משתמשות בזהות סביבת העבודה ומסננות את השאילתות לפיה.

תעודת ה־CA הציבורית נשמרת ב־`certs/supabase-prod-ca-2021.crt` ומועתקת לתמונת השרת. מקורה בקישור Download certificate בהגדרות המסד של Supabase. אימות TLS נשאר פעיל, כולל בדיקת שם השרת. מאגר החיבורים של מופע שרת בענן מוגבל לחיבור אחד. לא נעשה שימוש בשאילתות מוכנות בעלות שם או במצב session הנשמר בין עסקאות.

בדיקת האבטחה של Supabase מאשרת ש־RLS פעיל בכל תשע טבלאות היישום. ההודעות על RLS ללא policies צפויות: Data API כבוי, אין גישה דרך תפקידים ציבוריים, והאפליקציה ניגשת דרך שרת PostgreSQL בלבד. קיימת אזהרת ארגון על התקנת הרחבת vector בסכמת public; היא אינה פותחת גישה לטבלאות, אך אפשר להעביר את ההרחבה לסכמה נפרדת במיגרציה עתידית עם התאמת search_path בכל הסביבות.

## אזור הרצה ומגבלות

`vercel.json` מגדיר את `fra1`, פרנקפורט, ופרויקט Supabase נוצר ב־`eu-central-1`. המטרה היא להריץ את השרת ואת המסד באותו אזור באירופה.

ב־Vercel גודל קובץ אישי מוגבל ל־4MiB כדי להשאיר מקום למעטפת הבקשה תחת מגבלת ההעברה של הפלטפורמה. בהפעלה מקומית המגבלה נשארת 12MiB. לשתי הסביבות יש מגבלת 160 עמודים.

`Dockerfile.vercel` אורז את Next.js ואת תהליך Python באותה תמונת Container Runtime. יכולת זו של Vercel נמצאת ב־Beta. קובצי סודות, מסמכים מקומיים ונתוני הפיתוח מוחרגים מה־Docker build. בקובץ התמונה מותקנים המודל המקומי ותלויות Python.

## בדיקות לפני הפעלת ההעלאות

```powershell
npm.cmd ci
npm.cmd run setup
npm.cmd run lint
npm.cmd run typecheck
npm.cmd test
npm.cmd run build
npm.cmd run e2e
npm.cmd run eval -- --check
```

בדיקות מצב הענן המקומיות מאמתות הפרדה בין סביבות עבודה, חסימת העלאות בלי קוד, חתימת cookie, הגבלת העלאות מקבילות, מכסת השוואות ומחיקה. הן משתמשות במסד בזיכרון. החיבור ל־Supabase והמיגרציות נבדקו גם מול המסד בענן; לפני שינוי תצורת Production יש לבדוק העלאה, קליטה, השוואה, פתיחת מקור ובידוד דפדפנים באתר שנפרס.

הפעלת מצב הדמו המוכן מראש נבדקת ללא חיבור למסד וללא קריאה לספק מודל. יש להחליף את משתני הסביבה ולבדוק מחדש לפני פתיחת העלאות ו־AI חי למשתמשים.
